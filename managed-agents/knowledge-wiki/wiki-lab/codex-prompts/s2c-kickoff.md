## 要做的

### 1. 四处格式修改

**detail 带类型，不再写成字符串。**

- 模型输出 Schema 里，事件、义务、关系、陈述四类记录各有自己带类型的 detail 对象，字段和枚举从 `records.py` 的正式定义生成；用 strict 模式支持的 `anyOf` 区分记录类型。
- 任何字段都不能是"装着 JSON 的字符串"。
- `extras` 只留下真正少用的字段（components、additivity、origin、dimensions、limitations、date_notes），而且这些字段也要带类型。
- 说明类字段（description、note、reason 等）只写摘录和其他字段表达不了的内容，不复述摘录，也不写"与后续签约分别记录"这类关于抽取过程的话。代码统计这些字段的总字数，写进报告。

**表格加表级维度。** S2b 里 p93"按单项计提"和"按组合计提"两张表的"合计（坏账准备）"展开成了同一个键（`S34.s12-t004-r007-c002`）。

- 表可以带维度，展开时加到该表的每一格上。表名或表头里能区分同类表的限定词（计提方法、报表范围、产品或地区口径等）要写成表级维度。
- 代码检查：同一块内，来自不同表的两格键相同、数值不同时，进软规则队列。

**表格行可以带自己的期间。** S42 Key Changes 表的期间写在行名里（"2026E EBITDA (m)"），列是"原预测、本次预测"。S2b 把期间塞进了指标名，原预测和本次预测也没分开（`S42.s01-T1-r002-c001`）。

- 行可以覆盖期间和期间类型；这时列只提供其他维度。上面这个例子应该展开成：期间 2026E，指标 EBITDA，维度为原预测或本次预测。

**每块带章节路径。** S2b 的 R1 只给了 p111–112，模型看不出这是合并报表附注，范围只能写"未知"。

- 代码把 `chunks.json` 里每块的章节路径（如"第八节 财务报告 > 七、合并财务报表项目注释 > 固定资产"，编号按原文）放进来源元数据。覆盖模式和请求模式都放；请求模式按请求页码找所属章节。
- 加一条单元测试，确认请求模式的 prompt 里带上了章节路径（不用调用模型）。

**不推导数值。** S46 有 4 条股权关系被拒收：模型从 "wholly-owned" 自己推出了 100%，摘录里没有这个数。

- prompt 写明：`numbers` 只放原文印出的数（阿拉伯数字或整数词），不推导、不换算出原文没有的数。没有印出数值的关系，`numbers` 留空。
- 硬规则不变。

prompt 版本号改为 `extract-records-s2c-1`。

### 4. 对照和检查

**成本**：S34.s12、S46、S50、S42.s01 四块，各列 S2、S2b、S2c 三版的输入、缓存、输出、推理 token，耗时，展开格数，硬拒收数，软规则标记数，每格（或每条）的输出 token。S2b 的 S34.s12 是初版 prompt 的结果，注明这一点。

**非表格记录的体积**：按字段统计 S46、S50 每条记录的平均字符数（detail、摘录、说明文字、其他），和 S2b 对比，确认 `extras` 字符串的问题已经消失。

**推理强度**：S34.s12、S50 两块，ultra、high、medium 三档逐项对比输出 token、推理 token、耗时、硬拒收、软规则标记。质量用配对比较：

- 以 ultra 的结果为基准，较低档位的展开记录按对象键加数值和它配对；
- 列出只在一边出现的记录，以及键相同、数值或关键字段不同的记录；
- 差异逐条对照冻结页判断哪边对。差异超过 20 条的，固定种子抽 20 条判断，其余只计数。

最后给出建议：抽取用哪一档。

**定点复查**：S2b 抽查里的问题，逐条写修好了没有，附记录编号：

- p93 单项计提和组合计提共用一个键；
- S42 Key Changes 的期间和原预测、本次预测；
- S46 的 4 条股权关系（S1 对照的漏抽）；
- S34.s12 记录的合并范围是否填上了。

**语义抽查**：第 2–5 次的展开记录按块分层，固定种子抽 20 条，逐条对照冻结页判断，判为正确、错误（写错误类型）或拿不准，附页码依据。

**外推更新**：用 S2c 的密度（推理档位用你建议的那一档）替换 S2b 外推里对应的小节，重算 S34 全份和 P0 的 53 份。没重测的小节沿用 S2b 的数，并注明。
